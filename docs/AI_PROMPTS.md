## 二、AI 工具与 harness 清单

| 类别 | 工具 / harness | 在本次开发中的用途 |
|---|---|---|
| 对话式 AI 助手 | Trae | 需求拆解、代码生成、bug 定位修复、文档撰写 |
| 文档读取 | lark-doc skill（docs +fetch / +media-download） | 读取飞书机试文档原文、下载题目一视觉稿图片 |
| 视频分析 | OpenCV（Python 自定义脚本） | 对 `p.mp4` 抽帧、帧间差分定位高差异区间、生成时间线缩略图，还原动效时序 |
| 脚手架 | Vite 5 + react-native-web 0.19 + TypeScript | RN 标准组件一套代码，H5 / 原生 RN 双端可跑 |
| 动画 | RN `Animated`（timing + Easing 插值） | 浮层滑入、红包两阶段飞行、高亮闪烁 |
| 验证 | `npm run dev` / `build` / `typecheck` + 浏览器实测 | 逐项核对交互与动效、类型检查 |

> 本次未使用第三方 MCP 服务。harness 即上表「文档读取 skill + 视频分析脚本 + RN/Vite 脚手架 + 验证命令」的组合，均可在本仓库内复现：提示词即第一节原文，产出入 `src/` 与 `docs/`。

## 三、AI 参与的工作流

```
读飞书文档（lark-doc）
  → 下载视觉稿 / 拆帧分析动效视频（OpenCV）
  → 创建 RN+Vite 脚手架，AI 生成组件与动画代码
  → 本地起服务逐项验证，差异反馈给 AI 迭代
  → 输出提交材料（README / docs / 题目三邮件正文）
```

约束在提示词中一次说清：只用 RN 标准 API 保证多端一致、落点必须券图正中、动效时序对齐录屏。
