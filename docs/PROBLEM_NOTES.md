# 题目拆解与实现说明

## 一、题目理解

### 题目一：还原视觉稿（地址选择列表）
- **核心**：第三行布局——标签（行首）+ 地址两行折行 + 第二行右侧红色倒计时提示。
- **标签**：字数不固定，宽度自适应；可放行首（start），也可放第二行结尾（end，宽度 ≤ 50%）。
- **地址**：最多两行。
- **多端**：RN、微信、H5、支付宝、抖音表现一致；完成至少 2 端。

### 题目二：还原动效（优惠券浮层）
- 券浮层：底部弹出，内部优惠券列表，支持上下滑动。
- 点击领券 → 暴涨 1~4 张新券。
- 暴涨后的券有**抛物线动效**，**落点必须落在券图正中间**。
- 结束之后新领到的券**高亮闪烁**。
- 多端一致，完成至少 2 端。

### 题目三：邮件正文回答 AI 工具使用情况
- 见 `docs/ANSWER_Q3.md`。

## 二、实现方案

### 技术选型
RN + Vite 脚手架：所有组件使用 react-native 标准 API，通过 `react-native-web` alias 让 Vite 打包出 H5；同一套代码可用 Metro 跑原生 RN。即「一套代码，RN + H5 两端零改动」。

### 题目一布局算法（Q1AddressList）
```
每条地址 = [单选圈] [标签(start)...] 地址line1(1行省略)
                [地址line2(1行省略)] [标签(end)≤50%] [附加提示]
                [联系人 张先生 112****3838]
```
- start 标签 `flexShrink: 0` 宽度随内容。
- end 标签 `maxWidth: '50%'`。
- `numberOfLines={1}` + `ellipsizeMode="tail"` 保证地址最多一行/两行且跨端一致。

### 题目二动画实现（Q2CouponSheet）
1. **浮层入场**：`Animated.timing(translateY: 560 → 0)` + 遮罩 opacity。
2. **领券触发点**：列表顶部「每月领券」卡片（非底部一键领券、非普通券领券按钮）。点击后底部按钮变「领券中...」。
3. **领券流程**：800ms 后从券池随机选 `N ∈ [1,4]` 张新增到列表顶部，每月领券卡片保持可见。
4. **两阶段红包动画**：
   - **阶段1（1800ms）**：红包从每月领券卡片顶部 2/3 处出发，向卡片中心移动（慢）→ 停顿 → 向右分列成 N 个（从小到大，scale 0→1）。
   - **卡片消失**：分列完成后每月领券卡片消失（无动画）。
   - **阶段2（1200ms）**：红包从分列位置抛物线飞向各新增券的图片正中心，飞行中逆时针旋转 45° 不回正。
   - **落地即消失**：红包到达券图中心后立即移除，目标券 status → `claimed`（按钮变「已领取」+ 券图斜印）。
5. **高亮闪烁**：落地后目标券触发 3 次淡红背景呼吸动画；所有券闪烁结束后才弹「成功领取 N 张券」toast。
6. **定位准确性**：阶段1启动时记录券布局快照（卡片在时的位置），阶段2统一用「快照 y - cardOccupy（卡片高度+margin）」计算目标，避免卡片消失后 onLayout 不触发导致定位偏移；FlyingPacket 内部加 setTimeout 兜底防止 Animated 回调偶发未触发导致红包残留。
7. **收尾**：toast 淡出，底部按钮变「再看一次」，点击重置本次领取可重放（flashKey 用全局递增批次号，修复重放被跳过的 bug）。

## 三、验证结果
- `tsc --noEmit`：通过。
- `npm run build`：通过。
- H5 浏览器实测：
  - 题目一 6 条地址渲染正确，重点第三行（行首标签 + 地址两行折行 + 第二行末尾红色倒计时提示）正常，超长地址自动省略且标签不被挤掉。
  - 题目二浮层弹出、券列表上下滑动、点击「每月领券」触发暴涨、红包两阶段动画（卡片中心分列 → 飞向券图中心）、落地后券变「已领取」+ 高亮闪烁、闪烁结束后弹成功提示、底部变「再看一次」、重放正常、无红包残留。
