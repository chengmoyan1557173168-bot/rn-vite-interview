## 二、题目分析

### 题目一：还原视觉稿（地址选择列表）

**考点判断**：视觉稿本身不复杂，真正的考点全部集中在**第三行**——一个「文字流式排版 + 折行位置不定 + 尾部元素宽度受限」的布局难题。这是在考察对 Flexbox 折行行为和多端一致性的真实理解，而不是照抄 UI。

原文约束逐条拆解：

| 约束 | 技术含义 | 难点 |
|---|---|---|
| 标签字数不固定 | 标签宽度必须由内容撑开，不能写死 | 需区分「行首标签」与「结尾标签」两种排版角色 |
| 标签可在开头，也可作为第二行结尾 | 同一组件要支持两种排布模式 | 结尾标签是**折行后**的行尾元素，需与地址文本共享行空间 |
| 结尾标签最宽占 50% | 行尾标签需 `maxWidth: 50%` + 文本截断 | 百分比基准是整行容器，RN/H5 下 `maxWidth: '50%'` 行为需一致 |
| 地址最多两行 | 逐行 `numberOfLines={1}`，而非整体 `numberOfLines={2}` | 整体两行截断会导致结尾标签无处安放；必须 line1/line2 各自省略 |
| 五端一致（RN/微信/H5/支付宝/抖音），至少完成 2 端 | 只用各端公共子集 API | 禁用平台私有属性是跨端一致的前提 |

### 题目二：还原动效（优惠券浮层）

素材为一段 16.43s 的录屏（`p.mp4`，480x996），先用 OpenCV 抽帧 + 帧间差分定位高差异时间区间，再逐帧精读，还原出如下时间线：

| 时间点 | 动效 |
|---|---|
| 0.0s | 券浮层自底部滑入，内部券列表可上下滑动 |
| 点击「每月领券」 | 底部按钮进入「领券中...」态，约 0.8s 后随机暴涨 1~4 张新券插入列表顶部 |
| 暴涨后 | 红包从「每月领券」卡片出发 → 移至卡片中心 → 停顿 → 向右分列成 N 个（scale 0→1） |
| 分列后 | 卡片消失，红包沿**抛物线**飞向各新券图片正中心，飞行中逆时针旋转 45° |
| 落地 | 红包消失，目标券变「已领取」（按钮置灰 + 券图斜印）并**高亮闪烁 3 次** |
| 收尾 | 全部闪烁结束 → 弹「成功领取 N 张券」toast → 底部按钮变「再看一次」可重放 |

**考点判断**：

1. **落点必须落在券图正中间**（原文硬性要求）——考察「动画目标坐标」与「列表布局」的联动，列表可滚动、卡片会消失，坐标系随时在变，这是本题最大的坑。
2. **动效时序还原度**——暴涨数量随机、分列、抛物线、闪烁，缺一不可。
3. **多端一致**——动画只能用 RN 标准 `Animated`，不能碰平台私有 API。
4. **可重放**——「再看一次」意味着整个流程的状态必须能干净复位。

## 三、技术选型

```
React 18.2 + react-native 0.74.5（仅标准组件与 Animated API）
        + react-native-web 0.19（Vite alias）
        + TypeScript 5.5 + Vite 5.4
```

- **一套源码，RN + H5 两端零改动**：所有 UI 只用 `View / Text / Image / ScrollView / Animated` 等标准 API，H5 端经 `react-native-web` alias 由 Vite 打包，原生端换 Metro 入口（`src/index.js`）即可，业务代码不动。
- 选 RN 而非 taro3：题目原文点名建议 RN，且本题二动画对 `Animated` 插值依赖较深，RN 原生 API 语义最直接。
- 跨端一致策略：布局只用公共子集属性（`numberOfLines`、`maxWidth: '50%'`、flex 三件套），动画只用 `Animated.timing` + `Easing`，`useNativeDriver` 按属性白名单开启。

## 四、实现要点

### 题目一（`src/components/Q1AddressList.tsx`）

```
每条地址 = [单选圈] [标签(start)...] 地址line1(1行省略)
                 [地址line2(1行省略)] [标签(end)≤50%] [红色倒计时提示]
                 [联系人 张先生 112****3838]
```

- 行首标签：`flexShrink: 0`，宽度随内容自适应。
- 结尾标签：`maxWidth: '50%'`，超宽自动截断，挤占的是 line2 的剩余空间。
- 地址两行：line1 / line2 各自 `numberOfLines={1}` + `ellipsizeMode="tail"`，保证「最多两行」且任一行超长都优雅省略，五端行为一致。

### 题目二（`src/components/Q2CouponSheet.tsx`）

动效状态机：`idle → claiming(800ms) → phase1(1800ms) → phase2(1200ms) → flashing → success`。

关键设计与踩坑：

1. **红包落点居中（核心难点）**
   - 列表可滚动 + 「每月领券」卡片会消失，红包飞行期间坐标系不断变化。
   - 方案：**阶段1 启动时拍布局快照**——记录目标券位置（`targetLayouts`，含 `h`，缺省 96）与卡片占位 `cardOccupy`；阶段2 用「快照 y − cardOccupy」推算卡片消失后的新位置，并实时扣减 `scrollY`。
   - 落点计算：`centerY = finalY + cardH / 2 − scrollY − PACKET_SIZE / 2`，即券图垂直中点。
   - 飞行中若列表被用户滚动，用 `listLayouts` 实时布局 + scrollY 双通道纠偏。
2. **防重入**：布局轮询与 5s 兜底定时器都会尝试启动动画，`launch()` 内加 `launched` 标志保证只启动一次；阶段1→阶段2 汇合点同样加 `phase2Started` 防重入，否则红包会重复生成后闪没。
3. **Animated 回调兜底**：每个飞行动画内 `setTimeout(duration + 150ms)` 兜底，防止个别端 completion 回调偶发不触发导致红包残留。
4. **闪烁批次控制**：以全局递增的 `flashKey`（批次号）驱动高亮，避免重放时相同 key 被跳过；全部券闪完才弹 toast。
5. **重放复位**：`handleReplay` 清空券池的 `listLayouts` 缓存与 `targetLayouts` 快照，防止旧坐标残留造成落点偏移。

验证结论（H5 实测）：

- 题目一：6 条地址渲染正确；第三行（行首标签 + 两行地址折行 + 第二行末尾红色倒计时）符合视觉稿；超长地址自动省略且标签不被挤掉；结尾标签超宽时截断且不超过 50%。
- 题目二：浮层滑入、列表上下滑动、「每月领券」触发暴涨（1~4 张随机）、红包出发→分列→抛物线飞行→券图正中心落地、目标券变「已领取」+ 高亮 3 次、全部闪完弹 toast、底部变「再看一次」且可干净重放、连续重放无红包残留、无落点偏移。
- `npm run typecheck` / `npm run build` 均通过。

## 六、已知取舍

- 交付 RN + H5 两端（满足「至少 2 端」），小程序三端未单独出包——源码零依赖平台 API，接入 taro3/rn-web 同构方案即可扩展。
- 红包旋转方向、停顿时长等细节以录屏逐帧比对为准，个别毫秒级差异做了主观取舍。
