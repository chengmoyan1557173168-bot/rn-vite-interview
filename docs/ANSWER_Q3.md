## 一、日常开发中如何使用 AI，占比多少

AI 已嵌入我日常开发的各个环节，常规业务开发中 AI 产出约占 60%~70%，具体分布：

- **需求拆解与方案设计**：把 PRD / 视觉稿拆成组件树、状态机、数据模型，先对齐方案再动手。
- **业务代码编写**：表单、列表、弹层、CRUD 等样板代码交给 AI 生成，我负责 review 与联调。
- **动效与复杂交互**：让 AI 产出动画时序与插值方案，我针对多端差异做适配取舍。
- **Debug 与重构**：把报错堆栈、可疑代码喂给 AI 拿到假设与排查路径，验证后再修。
- **测试与自测**：补单测用例、构造边界数据、生成最小可复现 demo。

规律是：确定性越高、上下文越足的部分（组件、样式、状态管理），AI 占比越高；越涉及视觉还原、业务判断、跨端取舍的部分，我投入越多。**AI 负责提效，不替我做决策。**

## 二、使用的工具、工作流与 skill / mcp / plugin

**主要工具**：豆包 / 豆包编程助手（日常主力），配合 IDE 内代码补全与对话式助手。

**常用工作流**：

1. **先给上下文，再要方案**——报错堆栈、组件代码、截图/视觉稿一起给，不丢一句话过去。
2. **生成 → 实测 → 追问**——AI 产出后立刻本地跑起来，把实际表现差异反馈回去迭代，闭环到符合预期为止。
3. **约束先行**——多端一致、性能、可维护性这类硬约束，在提示词里一次说清，避免反复返工。
4. **沉淀复用**——把高频需求（列表页、弹层、动画）沉淀成可复用 skill / 模板。

**常用 skill / mcp / plugin**：文档与表格类 skill（材料转结构化产出）、图片/视频素材分析工具（视觉稿与动效拆解）、浏览器自动化与文件处理 harness、定时任务/数据看板类能力。

**本次机试的完整 harness 实例**（详见仓库 `docs/AI_PROMPTS.md`）：读飞书文档 → 下载视觉稿与动效视频 → OpenCV 抽帧还原时间线 → 创建 RN+Vite 脚手架 → 生成组件与动画 → 本地起服务逐项验证 → 输出提交材料。期间实测发现的红包闪现与落点偏移两个 bug，均由 AI 定位根因、我 review 后合入修复——这正是我主张的协作方式：**它给速度，我做验收。**

## 三、除了写代码，还用 AI 做什么

- **需求与文档**：PRD 解读、技术方案、接口文档、汇报材料起草与润色。
- **设计还原**：视觉稿分析、动效拆解、多端布局规则落地（本次题目二即是）。
- **数据与调研**：技术选型对比、竞品分析、性能数据整理与结论提炼。
- **沟通协作**：会议纪要、邮件/IM 措辞优化、跨团队信息同步。
- **质量保障**：code review 辅助、测试用例生成、线上问题排查、发布检查清单。
