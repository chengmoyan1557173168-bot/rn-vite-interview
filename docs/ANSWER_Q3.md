## 一、日常开发中如何使用 AI 编码，AI 占比

AI 已深度嵌入我的日常开发流程，**AI 辅助编码在常规开发中的占比约 60%~70%**。具体体现在：

- **需求拆解与方案设计（10%）**：用 AI 快速把 PRD / 视觉稿拆成组件树、状态机与数据模型，先对齐方案再动手，减少返工。
- **业务代码编写（40%）**：重复性、样板化代码（表单、列表、弹层、CRUD、格式化）基本交给 AI 生成，我负责 review 与落库。
- **动效与复杂交互（10%）**：用 AI 生成动画时序（抛物线、入场/出场、状态联动）并针对多端差异做适配。
- **Debug 与重构（20%）**：报错信息、线上问题的原因定位，AI 先给假设与排查路径，我验证后修复。
- **测试与自测（10%）**：让 AI 补单测用例、构造边界数据、生成可复现的最小 demo。

越靠近「确定性高、上下文强」的部分（如组件、样式、状态管理），AI 占比越高；越靠近「业务判断、视觉还原、跨端适配」的部分，我的投入越高，AI 负责提效而非决策。

## 二、使用的 AI 工具、常用工作流、常用 skill / mcp / plugin

**主要工具**
- 豆包 / 豆包编程助手（主力日常编码）
- 以及常用的代码补全与对话式 IDE 助手配合使用

**常用工作流**
1. **「先给上下文，再问方案」**：把报错堆栈、组件代码、截图/视觉稿一并喂给 AI，而不是只丢一句话。
2. **「生成 → 自测 → 追问」**：让 AI 产出后，我立刻本地跑起来验证，再把结果差异反馈回去迭代，形成闭环。
3. **「约束先行」**：多端一致、性能、可维护性是硬约束，在 prompt 里一次说清，避免反复。
4. **「沉淀模板」**：把高频需求（列表页、弹层、动画）沉淀成可复用的 skill / 模板，下次一键生成。

**常用 skill / mcp / plugin**
- 文档/表格/幻灯片类 skill（快速把材料转成结构化产出）
- 图片/视频素材类工具（视觉稿、动效拆解）
- 浏览器自动化与文件处理类 harness
- 定时任务 / 提醒类能力，用于后台监控与例行检查
- 数据看板与可视化类 skill，用于把数据结论转成图表

**harness 组合示例**（本次机试即是实例，详见 `docs/AI_PROMPTS.md`）：
- 「读飞书文档 → 下载视觉稿/视频 → 拆帧分析动效 → 创建 RN+Vite 脚手架 → 写组件 → 本地起服务验证 → 输出提交材料」是一条完整的 AI 流水线。

## 三、除了写代码，还用 AI 完成工作中的什么事项

- **需求与文档**：PRD 解读、技术方案、接口文档、汇报材料的起草与润色。
- **视觉/设计还原**：截图/视觉稿分析、动效拆解、多端布局规则落地。
- **数据与调研**：技术选型对比、竞品分析、性能数据整理与结论提炼。
- **沟通与协作**：会议纪要整理、邮件/IM 措辞优化、跨团队信息同步。
- **质量保障**：代码 review 辅助、测试用例生成、线上问题排查、发布检查清单。

总的来说，AI 是「从 0 到 1 的加速器 + 从 1 到 100 的执行器」，我把 AI 当作团队里的高级工程师伙伴：它负责快，我负责对；它给方案，我做决策与验收。
